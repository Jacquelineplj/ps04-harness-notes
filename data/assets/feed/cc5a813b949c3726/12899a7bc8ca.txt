RATED: Reliability-Aware AI Agent Tool Retrieval
via Execution Dynamics
Abstract.
As AI agents increasingly rely on external tools, accurate retrieval is essential for reliable behavior. Existing methods optimize semantic relevance but largely ignore tool availability during execution. To address this gap, we propose RATED (Reliability-Aware Tool retrieval via Execution Dynamics), a retrieval framework that combines robust semantic matching with dynamic reliability adaptation. RATED employs a frozen dual-encoder with contrastive fine-tuning for semantic matching, and a lightweight contextual bandit module that re-ranks candidates based on real-time execution feedback. This design enables rapid adaptation to runtime tool failures without expensive model retraining. We introduce EcoAgent, a benchmark of 5,172 real-world tools and over 210,000 query–tool pairs for offline retrieval and dynamic reliability evaluation. Experimental results demonstrate that RATED achieves a 52.2% relative MRR improvement over the ToolLLM API retriever on real-world queries, and reduces fault selection rate from 86.2% to 2.9% under severe API outage scenarios with a 30% failure rate, while incurring negligible latency overhead of less than 1 ms over encode-only inference. Code and dataset are available at https://github.com/Elliotes/EcoAgent.
Keywords:
AI agents; Tool retrieval; Contextual bandits; Contrastive learning
1. Introduction
Large Language Models (LLMs) have demonstrated impressive capabilities in natural language processing but are inherently unable to execute real-world actions (Li et al., 2025; Naveed et al., 2025). To overcome this limitation, recent systems integrate LLMs with external tools and APIs (Mialon et al., 2023; Schick et al., 2023), yielding autonomous AI agents that fulfill actionable requests, such as querying live databases or managing enterprise workflows (Dong et al., 2024). The fundamental bottleneck for these systems has shifted from text generation to accurately identifying and retrieving the correct entry from vast, growing tool repositories (Patil et al., 2023).
To address the tool retrieval challenge, existing research has focused on optimizing semantic relevance for Large Language Models (LLMs). Foundational works like ToolLLM (Qin et al., 2023) and ToolExpNet (Zhang et al., 2025) treat tool retrieval as a static ranking task. They use dense retrieval or experience networks to map queries to tool documentation based entirely on semantic relevance. While approaches such as TRFeedback (Xu et al., 2024) and ToolRL (Qian et al., 2025) incorporate execution feedback, they still aim to optimize how the LLM plans and invokes tools in a static environment. However, real AI agent tool ecosystems are far from static and highly unreliable. We crawl tool catalogs from LangChain (LangChain AI, 2023), CrewAI (CrewAI, 2024), LlamaIndex (LlamaIndex, 2024), and n8n (n8n, 2024) to reveal the severity of this issue. As Figure 1 shows, despite rapid growth, over 50% of these tools exhibit critical flaws like broken links and missing authentication. Many tools are functionally similar, so retrieval cannot rely on semantics alone to identify which ones will execute successfully. To overcome this challenge, the system must adapt dynamically during execution. When a tool fails at runtime, the system must promptly adjust candidate ordering between requests. ToolRL cannot achieve this prompt adjustment because it uses Group Relative Policy Optimization (GRPO) (Shao et al., 2024) to update the LLM from batched trajectories and still targets the planner. Contextual bandits (Li et al., 2010) effectively address this problem. They condition each decision on the current query and update from each individual execution outcome. Moreover, they observe feedback only for the selected tool and make immediate adjustments without retraining the semantic retriever.
In this paper, we propose RATED (Reliability-Aware Tool retrieval via Execution Dynamics), a retrieval framework that dynamically adapts to runtime tool failures without human intervention. First, we introduce EcoAgent, a benchmark of 5,172 real-world agent tools and over 210,000 query–tool pairs. Second, RATED employs a dual-encoder fine-tuned with a contrastive objective for semantic matching, together with a lightweight contextual bandit that re-ranks the top-\(K\) candidates using a prior based on metadata and execution feedback, enabling the system to avoid failing tools. Experiments show that RATED alone keeps fault selection below 3% and recovers at both failure rates. Under a 30% failure injection protocol, RATED reduces fault selection rate to 2.9%, compared with 86.2% for the ToolLLM API retriever, while adding only 0.172 ms latency per step over encode-only inference.
2. The EcoAgent Benchmark
We construct EcoAgent, a benchmark comprising two complementary datasets. EcoAgent complements existing tool-use datasets with metadata reliability scores for every tool and with an evaluation protocol for injected execution failures. EcoAgent-Syn supports robust training with synthetic pairs, and EcoAgent-Real supports rigorous evaluation using real-world queries. We aggregate 5,172 real-world tool definitions from four open-source AI agent platforms, namely LangChain, CrewAI, LlamaIndex, and n8n. Metadata are normalized into a shared schema with functional descriptions, names, endpoints, and authentication fields, which supports retrieval text construction and reliability scoring. To operationalize tool quality, each tool receives an automated metadata reliability score between 0 and 1 from three weighted signals, namely name–description consistency, source credibility, and documentation quality, which Section 3.3 defines. The benchmark does not rely on manual per-tool ratings. Tools with scores of at least 0.8 are marked as reliable, identifying 2,940 tools, or 56.8% of the repository. The encoder is trained only on EcoAgent-Syn, while retrieval and dynamic experiment results are validated on the EcoAgent-Real test split, with hyperparameters selected on the validation split.
We build EcoAgent-Syn with Gemma-3-1b (Gemini Team, 2025). For each tool, the model receives the tool name, functional description, and metadata as context and generates 10–20 task-oriented queries. Queries are restricted to 5–120 words, and near-duplicates with Jaccard similarity above 0.7 are removed to preserve intent diversity. Figure 2 shows the prompt template, which we also release with the dataset. To improve robustness against spurious correlations, each query is paired with hard negatives from SBERT (Reimers and Gurevych, 2019) retrieval and random negatives. EcoAgent-Syn links 69,501 unique synthetic queries to 5,172 ground-truth tools, with 70,122 positive pairs and 140,244 negative pairs. For evaluation under realistic language distributions, we build EcoAgent-Real from ToolBench (Qin et al., 2023). Because the original dataset lacks ground-truth mappings to our tool repository, we implement a semi-automated labeling pipeline. GTE-Large (Li et al., 2023) retrieves the top-5 candidates per query, discards pairs with cosine similarity below 0.7, and Gemma-3-1b verifies the remainder, retaining only pairs with functional match scores of at least 0.85. Human experts review a stratified sample of 200 queries and agree with the LLM verifier on 94% of cases. After filtering and deduplication, EcoAgent-Real contains 6,379 unique queries and 9,946 verified query–tool pairs.
3. Methodology
3.1. Problem Setup
We formulate agent tool retrieval as sequential decision making over a shared repository. Let \(\mathcal{U}=\{a_{1},\dots,a_{M}\}\) denote the tool pool, where \(M{=}5{,}172\) in EcoAgent. At step \(t\), the agent issues query \(q_{t}\). The retriever returns a candidate set \(\mathcal{A}_{t}\subset\mathcal{U}\) with \(|\mathcal{A}_{t}|=K\), and the policy selects one tool \(a_{t}\in\mathcal{A}_{t}\) for execution. The objective is to maximize the probability of successful execution. Unlike static retrieval with a fixed mapping \(f(q,a)\rightarrow\{0,1\}\), production agents must cope with tools that fail at runtime, where tool utility depends on semantic relevance \(S_{\text{sem}}(q_{t},a)\) and time-varying reliability. After execution, only the chosen tool yields binary feedback \(y_{t}\in\{0,1\}\), yielding partial feedback that we address with contextual bandits (Abe et al., 2003). Figure 3 summarizes the RATED pipeline.
3.2. Semantic Perception Module
The semantic perception module implements the first stage of RATED. Given \(q_{t}\), it scores all tools in \(\mathcal{U}\) by \(S_{\text{sem}}\) and returns the top-\(K\) candidate set \(\mathcal{A}_{t}\) defined in Section 3.1. The semantic encoder is based on DRAGON (Lin et al., 2023), fine-tuned on EcoAgent-Syn and frozen at deployment. New tools can be added by encoding their documentation with \(f_{T}\) without retraining the encoders.
3.2.1. DRAGON Dual-Encoder Architecture
DRAGON provides separate query encoder \(f_{Q}\) and tool encoder \(f_{T}\), which suits settings where user queries and tool documentation follow different lexical patterns. For query \(q\) and tool \(a\), we take CLS representations and L2-normalize them. The semantic relevance score is the dot product of the normalized vectors.
| (1) |  | \[\mathbf{e}_{q}=\mathrm{norm}(f_{Q}(q)),\quad\mathbf{e}_{a}=\mathrm{norm}(f_{T}(a))\] |  |
| (2) |  | \[S_{\text{sem}}(q,a)=\mathbf{e}_{q}^{\top}\mathbf{e}_{a}\] |  |
3.2.2. Contrastive Fine-tuning on EcoAgent-Syn
Although DRAGON is effective for open-domain retrieval, agent tool descriptions use specialized API terminology. We fine-tune \(f_{Q}\) and \(f_{T}\) on EcoAgent-Syn with an in-batch InfoNCE objective (van den Oord et al., 2019). For a batch of \(B\) positive pairs \(\{(q_{i},a_{i}^{+})\}_{i=1}^{B}\), we optimize
| (3) |  | \[\mathcal{L}_{\text{InfoNCE}}=-\frac{1}{B}\sum_{i=1}^{B}\log\frac{\exp(\mathbf{e}_{q_{i}}^{\top}\mathbf{e}_{a_{i}^{+}}/\tau)}{\sum_{j=1}^{B}\exp(\mathbf{e}_{q_{i}}^{\top}\mathbf{e}_{a_{j}^{+}}/\tau)}\] |  |
where \(\tau\) is a temperature hyperparameter. Hard negatives from EcoAgent-Syn construction in Section 2 are used in training. In-batch negatives provide additional contrast during optimization.
3.3. Reliability-Aware Re-ranking
The second stage re-ranks \(\mathcal{A}_{t}\) from Section 3.2 using operational signals while the semantic encoders remain frozen. At step \(t\), the context is the query embedding \(\mathbf{x}_{t}=\mathbf{e}_{q_{t}}\in\mathbb{R}^{d}\), the policy selects \(a_{t}\in\mathcal{A}_{t}\), and observes reward \(y_{t}\in\{0,1\}\) only after execution, where \(y_{t}{=}1\) denotes success and \(y_{t}{=}0\) denotes errors or timeouts.
Tools with little execution history are initialized from catalog metadata. We define a static prior \(r_{\text{static}}(a)\in[0,1]\) from three signals used in benchmark construction in Section 2, namely name–description consistency \(r_{\text{cons}}(a)\), source credibility \(w_{\text{src}}(a)\), and documentation quality \(r_{\text{qual}}(a)\).
| (4) |  | \[r_{\text{cons}}(a)=\cos(f_{\text{Enc}}(a_{\text{name}}),f_{\text{Enc}}(a_{\text{desc}}))\] |  |
| (5) |  | \[r_{\text{static}}(a)=\lambda_{1}r_{\text{cons}}(a)+\lambda_{2}w_{\text{src}}(a)+\lambda_{3}r_{\text{qual}}(a)\] |  |
where \(\sum_{i}\lambda_{i}=1\). These signals implement the catalog reliability score in Section 2, and all three read catalog fields only, so no manual rating is needed. For \(r_{\text{cons}}\), \(f_{\text{Enc}}\) is the SBERT encoder of Section 2, which embeds the tool name and its description, and we take the cosine of the two normalized vectors. For \(w_{\text{src}}\), each platform carries a fixed weight, namely 1.0 for an official listing, 0.9 for LangChain, CrewAI, and LlamaIndex, 0.8 for n8n, and 0.6 otherwise. For \(r_{\text{qual}}\), we standardize the description length and the tag-string length against their medians and pass \(0.6\,z_{\text{desc}}+0.4\,z_{\text{tag}}\) through a logistic function. The 0.8 threshold is used for benchmark statistics, while \(r_{\text{static}}\) initializes the bandit. Each arm bias is initialized as \(\mathbf{b}_{a}\leftarrow r_{\text{static}}(a)\cdot\mathbf{x}_{0}\), which covers the cold-start case, where a new or rarely used tool carries no execution history and is therefore scored from its catalog metadata.
At runtime, the system must adapt to dynamic failures such as API outages. Standard LinUCB (Li et al., 2010) weights all past observations equally and therefore adapts slowly when arm quality shifts over time. Alternatively, a global multi-armed bandit (Global MAB) (Auer et al., 2002) tracks shared or context-free arm statistics. It is cheaper to maintain but cannot model payoffs that depend on the current query context. To overcome these limitations, RATED adopts discounted LinUCB (Garivier and Moulines, 2011) with a separate linear model per tool. This choice addresses non-stationarity by down-weighting older rewards before each update, ensuring that recent failures change tool scores more quickly. Each tool \(a\) maintains \(\mathbf{A}_{a}\in\mathbb{R}^{d\times d}\) and \(\mathbf{b}_{a}\in\mathbb{R}^{d}\). The reliability score combines exploitation and exploration.
| (6) |  | \[S_{\text{bandit}}(\mathbf{x}_{t},a)=\hat{\boldsymbol{\theta}}_{a}^{\top}\mathbf{x}_{t}+\alpha\sqrt{\mathbf{x}_{t}^{\top}\mathbf{A}_{a}^{-1}\mathbf{x}_{t}}\] |  |
where \(\hat{\boldsymbol{\theta}}_{a}=\mathbf{A}_{a}^{-1}\mathbf{b}_{a}\). After executing \(a_{t}\) and observing \(y_{t}\), we update with discount \(\gamma\in(0,1)\).
| (7) |  | \(\displaystyle\mathbf{A}_{a_{t}}\) | \(\displaystyle\leftarrow\gamma\mathbf{A}_{a_{t}}+\mathbf{x}_{t}\mathbf{x}_{t}^{\top}\) |  |
| (8) |  | \(\displaystyle\mathbf{b}_{a_{t}}\) | \(\displaystyle\leftarrow\gamma\mathbf{b}_{a_{t}}+y_{t}\mathbf{x}_{t}\) |  |
Discounting emphasizes recent feedback and encourages timely switches to alternatives.
3.4. Hybrid Fusion for Tool Ranking
RATED fuses semantic, bandit, and metadata signals into one score over \(\mathcal{A}_{t}\). For query \(q_{t}\) and candidate \(a\in\mathcal{A}_{t}\), we define
| (9) |  | \[S_{\text{final}}(q_{t},a)=w_{1}S_{\text{sem}}(q_{t},a)+w_{2}S_{\text{bandit}}(\mathbf{x}_{t},a)+w_{3}r_{\text{static}}(a)\] |  |
where \(w_{1}+w_{2}+w_{3}=1\). Weights are tuned on the validation split and fixed for testing in Section 4. At each step, the system retrieves top-\(K\) tools by \(S_{\text{sem}}\), ranks \(\mathcal{A}_{t}\) by \(S_{\text{final}}\), executes the highest-scoring tool, and updates bandit parameters from \(y_{t}\). 4. Experiments
4.1. Experimental Setup
All experiments run on a single NVIDIA GeForce RTX 5070 GPU (12 GB VRAM). DRAGON is fine-tuned on EcoAgent-Syn for one epoch with batch size 8, learning rate \(1\times 10^{-5}\), 1,000 warmup steps, \(\tau=0.05\), mixed precision, and maximum sequence length 256. At inference, the system retrieves top-\(K{=}10\) tools by \(S_{\text{sem}}\) and re-ranks them with Eq. 9. The bandit uses \(\alpha=0.1\), \(\gamma=0.95\), and 2,000 warm-up pairs, with diagonal covariance updates for \(O(d)\) scoring at each step. Fusion weights tuned on the EcoAgent-Real validation split are \((w_{1},w_{2},w_{3})=(0.75,0.15,0.10)\). Static weights \((\lambda_{1},\lambda_{2},\lambda_{3})\) in Eq. 5 are \((0.5,0.3,0.2)\), and biases are initialized with \(\mathbf{x}_{0}=\mathbf{1}/\sqrt{d}\).

4.2. Evaluation Metrics
Offline retrieval is measured with MRR, Recall@1, and Recall@5 on the EcoAgent-Real test split. EcoAgent-Syn uses the same metrics for in-domain comparison. Dynamic reliability is evaluated over \(T{=}10{,}000\) sequential selections. At step \(t\), the policy selects \(a_{t}\) for query \(q_{t}\) with ground truth \(a^{*}_{t}\). The indicator \(\text{Status}(a,t)\in\{0,1\}\) denotes whether tool \(a\) is available under simulated failure injection. To simulate a persistent outage, the simulator ranks the \(N\) distinct ground-truth tools of the evaluation stream by frequency, skips the top 10%, and marks the next \(\rho N\) tools as failing, where \(\rho\) is the failure rate. The failing set is fixed before the run, and its tools stay unavailable from failure onset to the end. Metrics are averaged over the window after failure onset \(\mathcal{T}_{\text{post}}=\{2{,}001,\ldots,5{,}000\}\), which contains \(T_{\text{post}}{=}3{,}000\) steps.
| (10) |  | \[\text{Post-Fail SR}=\frac{1}{T_{\text{post}}}\sum_{t\in\mathcal{T}_{\text{post}}}\mathbb{I}(a_{t}=a^{*}_{t})\cdot\text{Status}(a_{t},t),\] |  |
| (11) |  | \[\text{FSR}=\frac{1}{T_{\text{post}}}\sum_{t\in\mathcal{T}_{\text{post}}}\mathbb{I}(\text{Status}(a_{t},t)=0),\] |  |
where FSR is the fault selection rate. Adaptation steps (AS) measure recovery speed using
| (12) |  | \[t_{\text{adapt}}=\min\{t:\text{SR}_{\text{window}}(t)\geq\theta\times\text{SR}_{\text{peak}}\},\] |  |
computed from failure onset with a sliding window of \(W{=}200\) steps, peak success rate before failure \(\text{SR}_{\text{peak}}\), and \(\theta{=}0.9\) at 20% failure rate or \(\theta{=}0.8\) at 30%. Static rankers without online feedback never reach the recovery target and are marked Failed.
4.3. Baselines
Retrieval baselines include lexical matchers TF-IDF (Spärck Jones, 1972) and BM25 (Robertson and Walker, 1994), dense encoders OpenAI Ada-002 (OpenAI, 2022), BGE-M3 (Chen et al., 2025), GTE-Large (Li et al., 2023), and E5-Large-v2 (Wang et al., 2024), and neural IR models DRAGON (Lin et al., 2023), which is not fine-tuned on EcoAgent-Syn, and SPLADE-v3 (Lassance et al., 2024). We also include a BGE-Reranker-v2-m3 (Chen et al., 2025) cross-encoder that re-ranks DRAGON top-50 candidates, and the ToolLLM API retriever (Qin et al., 2023). For dynamic evaluation, two reactive baselines share the DRAGON ranker: Health Check Blacklist permanently excludes any tool after one failed execution, and Retry (\(k{=}3\)) tries up to three candidates within one step and keeps no memory across steps. A batch GRPO proxy similar to ToolRL (Shao et al., 2024) updates weights periodically rather than online. RATED uses DRAGON fine-tuned on EcoAgent-Syn as the backbone and is evaluated as RATED (Full), RATED (w/o Contrastive), RATED (w/o Feedback), and RATED (w/ Global MAB).

4.4. Main Results
Table 1 reports offline retrieval on EcoAgent-Syn and the held-out EcoAgent-Real test split. RATED (Full) ranks first on Syn across all metrics, and RATED (w/o Contrastive) matches pretrained DRAGON on both benchmarks, which isolates the gain from contrastive fine-tuning. On EcoAgent-Real, RATED (Full) improves MRR by 52.2% over the ToolLLM API retriever but stays below Ada-002 and SPLADE-v3. High offline ranking accuracy on real queries therefore does not guarantee robust tool selection when tools fail at runtime.
Table 2 reports Post-Fail SR, FSR, and adaptation steps under 20% and 30% failure injection. Static retrievers, including ToolLLM and Ada-002, frequently select unavailable tools and never recover within the evaluation horizon. DRAGON (pretrained) and BGE-Reranker reduce FSR but remain unable to adapt online. Relative to RATED (w/o Feedback), RATED (Full) lowers FSR to 2.5% and 2.9% while it maintains Post-Fail SR above 82%, which is a \(7.3\times\) reduction over DRAGON (pretrained) and a \(30\times\) reduction over ToolLLM. Batch GRPO updates similar to ToolRL retain higher FSR, and health check blacklisting attains low FSR but recovers slowly. RATED (w/ Global MAB) stays inferior to the full model. These results support decoupling semantic matching from reliability estimation updated online from execution feedback.
4.5. Hyperparameter Sensitivity
Figure 4 reports Post-Fail SR and FSR under 20% failure injection for two grid sweeps over fusion and bandit hyperparameters. Panel (a) varies \(w_{1}\) and \(w_{3}\) with bandit settings fixed. Post-Fail SR rises with \(w_{1}\) and peaks at \(w_{1}=0.75\) with \(w_{3}=0.10\), whereas FSR grows slowly over the same range and stays in the low single-digit range throughout. We therefore select \(w_{1}=0.75\) and \(w_{3}=0.10\) on the validation split, which trades about one point of FSR for the highest Post-Fail SR. Panel (b) varies \(\gamma\) and \(\alpha\) with fusion weights fixed at the validated setting. Post-Fail SR is highest at \(\gamma=0.95\), where the three \(\alpha\) curves nearly coincide, and FSR again grows slowly with \(\gamma\). We therefore set \(\gamma=0.95\) and \(\alpha=0.1\) on the validation split.
4.6. Efficiency Analysis
We profile end-to-end inference at batch size 1 on the same hardware as Section 4. Table 3 reports average latency, P95 latency, and incremental overhead relative to DRAGON encoding only. The encode-only baseline averages 3.223 ms. RATED (w/o Feedback) applies only the static reliability prior in Eq. 5 and adds 0.025 ms. Contextual bandit re-ranking incurs modest additional cost. RATED (w/ Global MAB) adds 0.108 ms, and RATED (Full) adds 0.172 ms, reaching 3.395 ms average and 4.391 ms P95 latency. These overheads are far below batch GRPO updates similar to ToolRL at 17.839 ms average, which require periodic policy synchronization. Therefore, RATED is fast enough for interactive agent loops and still reduces fault selection.

5. Conclusion
We introduced RATED, a reliability-aware tool retrieval framework that combines DRAGON encoders fine-tuned with contrastive learning and contextual bandit re-ranking from execution feedback. On EcoAgent, RATED achieves strong in-domain retrieval and remains competitive on real-world queries. Under injected tool failures, it reduces fault selection to 2.5–2.9% FSR, \(7.3\times\) lower than static DRAGON, with only 0.172 ms added latency over encode-only inference. These results highlight the critical importance of incorporating execution feedback into retrieval systems for autonomous agents operating in dynamic environments, and demonstrate that RATED provides an efficient solution for reliable tool discovery in agent systems. Evaluating this cold-start path on newly added tools and validating RATED in live agent runtimes remain future work.
