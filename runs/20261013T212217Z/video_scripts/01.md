# The Harness Became the Variable: What Changed This Month

Runtime target: approximately 4 minutes 30 seconds (about 660 narration words)

## 1. Hook

**Visual:** Title card on dark background. Below the title, two stacked bars labelled "Cheap model, no harness — 3/10" and "Cheap model, with harness — 10/10".

**On-screen text:** The harness is now the measured variable

**Narration:** This month the harness stopped being a design opinion and became something you can measure. In one controlled experiment, the same brief run ten times per condition, a cost-optimized model went from three accepted runs out of ten to ten out of ten purely by adding a behavioral harness — while a frontier model passed all ten either way [01-c1]. Three independent strands landed in the same place, and here is our read: the levers arrived ahead of the instruments [01-c8].

## 2. The experiment

**Visual:** Quote card. Publisher line reads "Martin Fowler's site / Thoughtworks — 13 October 2026". Quoted text: "a cost-optimized model succeeded in only 3 of 10 unharnessed runs and all 10 with the harness."

**On-screen text:** Same brief. Ten runs each. Harness varied.

**Narration:** The clearest new evidence is a 13 October post on Martin Fowler's site, written by a Thoughtworks practitioner. Coding agents built the same API service with and without a behavioral harness, ten runs per condition. The frontier model passed every external evaluation in both conditions; the cheaper model only cleared three of ten without the harness, and all ten with it [01-c1].

## 3. The economics

**Visual:** Two cost bars side by side: "Harnessed cheap model — $0.273" and "Unharnessed frontier model — $0.406". Both tagged "10 of 10 accepted".

**On-screen text:** Same acceptance. About 33% cheaper.

**Narration:** The economics are the part worth staring at. The harnessed cheap model hit the same ten-for-ten acceptance as the unharnessed frontier model at roughly a third lower cost per run — twenty-seven cents versus forty-one [01-c2]. We read this as the first widely circulated result that varies the harness instead of holding it constant. The author himself frames it as a revised hypothesis, not a law [01-c8].

## 4. The instrument problem

**Visual:** Quote card. Publisher line: "ThinkingBox write-up, Hugging Face — 3 October 2026". Quoted text: "67.24% still terminated cleanly, invoked a state-changing tool, and reported no final tool error."

**On-screen text:** Clean exit. Wrong database.

**Narration:** If the harness is a lever, you need an instrument to tell whether pulling it helped. A 3 October write-up of ThinkingBox argues the common instrument is broken. ThinkingBox grades terminal backend database state instead of tool calls, and reports that across its executable-check failures, about two thirds terminated cleanly, invoked a state-changing tool, and reported no final tool error [01-c3]. A trajectory-based grader would have scored those runs as fine. Its summary line is blunt: a trajectory is a claim, database state is the evidence [01-c8].

## 5. Traces beat scores

**Visual:** Simple before-and-after table. Rows: "Unnecessary skill loads: 51 → 0", "Benchmark run cost: $11.85 → $8.34", "Correctness: unchanged". Source line: "Arize, Harbor and Phoenix walkthrough — 12 October 2026".

**On-screen text:** One tool description. 30% cheaper.

**Narration:** A smaller, more immediately actionable version of the same point came from a 12 October Arize walkthrough. Changing a single tool description eliminated fifty-one unnecessary skill loads and cut a benchmark run's cost by about thirty percent, with correctness unchanged [01-c6]. The authors stress that the score passed every time — only the trace revealed the waste [01-c6].

## 6. The levers vendors shipped

**Visual:** Two logo-free panels. Left: "Anthropic — dynamic workflows: Claude plans and writes its own orchestration program." Right: "Microsoft Agent Framework — managed semantic memory; Hyperlight-sandboxed CodeAct."

**On-screen text:** New levers. No independent measurement.

**Narration:** Anthropic announced dynamic workflows, covered in a 12 October Latent Space write-up: Claude itself plans and writes the orchestration program that launches sub-agents, replacing the prior requirement that developers configure a coordinator and a sub-agent roster [01-c4]. That is a vendor claim with no outside measurement attached. Microsoft shipped harness-layer primitives in Agent Framework — managed semantic memory through a Foundry memory provider, and Hyperlight-sandboxed CodeAct execution with an explicit isolation boundary, so model-generated code is isolated while registered application tools keep running in your own runtime with their own permissions [01-c5].

## 7. The measurement Microsoft did publish

**Visual:** Trace comparison graphic. Left column "A2A specialists: 6–7 model calls". Right column "Distributed skills over MCP: 3 model calls, about 22% more tokens". Source line: "Microsoft agent-framework blog — 16 September 2026".

**On-screen text:** Fewer calls ≠ less context

**Narration:** The most useful Microsoft item is not an announcement but a measurement. A 16 September side-by-side trace comparison found that moving specialist instructions into the orchestrator over MCP cut model calls from six or seven down to three per request — but consumed roughly twenty-two percent more total tokens [01-c7]. Fewer model calls did not mean less cumulative context, and the author is careful that this counts tokens, not dollars [01-c7].

## 8. Limits and takeaway

**Visual:** Split slide. Left: "Limits — one greenfield Java service; synthetic benchmark tasks; vendor items unmeasured." Right: "Do first — grade backend state, keep traces next to scores." Article URL and "Sources linked in description" at the bottom.

**On-screen text:** Build the instrument before you pull the lever

**Narration:** Now the honest part. The Fowler experiment is one greenfield Java service with an unusually detailed brief, and the author flags that legacy code, other languages and vague requirements are untested [01-c1]. ThinkingBox tasks are synthetic reconstructions [01-c3]. The vendor items have no independent measurement at all [01-c4][01-c5]. Missing entirely: open-source maintainers at scale, security researchers assessing the self-planning orchestration surface, and non-US builders. So our takeaway is narrow. Before adopting dynamic workflows or managed memory, build the state-based check first — grade the backend, not the transcript [01-c3] — and keep traces next to scores, because cost regressions hide behind passing suites [01-c6]. And if you run a cost-optimized model, the harness may be the cheaper purchase than the bigger model [01-c2]. The full article and every source are linked below.
