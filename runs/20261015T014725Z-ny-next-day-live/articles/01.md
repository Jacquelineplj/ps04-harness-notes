# The harness grew a second layer: what changed in agent infrastructure this month

The interesting work this month happened outside the agent loop. Vendors shipped orchestration and deployment primitives while practitioners at Uber, Anthropic and Credit Karma described building nearly the same surrounding systems without citing each other — and both camps report the same thing: the model and the loop are no longer the bottleneck.

## Orchestration topology is now an open design axis

Anthropic announced dynamic workflows, in which the lead agent writes its own orchestration program — launching agents, collecting results, managing information flow — instead of the developer pre-configuring a coordinator and a roster of subagents [01-c1]. That was described on Latent Space's 12 October writeup of the launch; developers can still pass in pre-configured specialists if they want [01-c1].

Microsoft's Agent Framework blog, in a 16 September post, pushes in what looks like the opposite direction: it argues that bounded domain competences should stop being specialist agents with their own model loops and instead move into the orchestrator's context as distributed skills, with only tools remaining remote over MCP [01-c2]. The post is careful not to overclaim — its own framing is that "an autonomous agent can remain an agent, while a bounded competence can become a skill" [01-c2].

We read these as complementary approaches to an unsettled design choice. Treat orchestration topology as something to design explicitly.

## Two practitioners, one stack, no cross-citation

The strongest evidence this month is not an announcement. On the Pragmatic Engineer podcast released 14 October, Uber's engineers describe an MCP gateway that auto-generates MCP specs from their existing Thrift and Protobuf IDL registry — and, later, projecting those same MCP servers as CLIs because the CLI pattern is more token-efficient than loading six MCP servers into context (around 29:19 and 36:39) [01-c4]. The host's framing at 0:53 is blunt: the harness is the easy part, and what's hard is all the things around it [01-c7].

Separately, at the AI Engineer talk published 14 October, Credit Karma's Harish Gaggar walks through a comparable stack for governed enterprise agents: an MCP gateway doing JWT exchange with session state in Redis, every tool reviewed by an internal security team before production, PII and unnecessary fields blocked before reaching the LLM, LangGraph as the agent framework, and a context optimizer (at 8:53, 10:12, 27:20) [01-c5]. He also enumerates the open questions that drove the build — memory recall across multi-day sessions, tracing, secrets never reaching the LLM or the memory DB (at 2:18) [01-c7].

Neither source cites the other. Two teams in unrelated industries independently converging on gateway + identity + context optimization + checkpointing is, in our reading, the clearest sign this layer is genuine engineering rather than vendor category-creation [01-c7].

LangChain's 9 October Managed Deep Agents video makes the identity half of that explicit as a product primitive: the developer declares, per connection, whether the agent acts on behalf of the calling user with that user's credentials, uses its own agent-scoped credentials, or uses a service account — with mid-task auth interrupts handled by checkpointing (at 9:29 and 9:52) [01-c6].

## The downstream blast radius

Simon Willison's 13 October link blog surfaced Anthropic's account of why it replaced Git: merged code changes went from roughly 2,500 per day in May 2026 to over 30,000 per day in September, with the replacement system built by seven people and the migration completed in five months [01-c3]. The stated requirements — a ~100 GB main-branch history and on the order of 25 million CI checkouts per day across developer environments, agent sandboxes and research jobs — describe a source-control problem created by agent throughput, not by headcount [01-c3][01-c7].

Research moved in the same direction. The LAGO paper, posted to arXiv on 14 October, proposes treating specialized agents as a persistent, reusable library of options managed by a meta-agent, reporting 58.6% on the full 500-task SWE-bench Verified split with a frozen Qwen3.5-35B-A3B in both roles [01-c8]. The interesting part is the architecture claim — reuse across tasks without weight updates — not the headline number [01-c8].

## What the evidence does not support

None of the vendor announcements carry independent measurement. Microsoft's own trace comparison is labelled by its author as a three-pair illustration, not a controlled performance or quality study [01-c2]. The Uber and Credit Karma accounts are self-reported descriptions of their own systems, including the token-saving figures, with no external verification [01-c4][01-c5]. LAGO's ablations are explicitly described by its authors as leaving component-level causality task- and model-dependent [01-c8]. And three perspectives are simply absent this month: independent open-source maintainers, non-US builders, and any security researcher who has actually probed the gateway patterns these companies describe.

## What this means for builders

If you are still optimizing the loop, you are probably optimizing the wrong thing. Budget this quarter for the layer around it — a tool gateway with real identity delegation, explicit per-connection credential semantics, context accounting, and whatever your CI and source control need to survive your own agents' output volume. Prefer the practitioner accounts over the announcements when choosing what to copy, and assume every number you have read this month is self-reported until someone outside the company checks it.
