# The harness grew a second layer: what changed in agent infrastructure this month

Runtime target: 4 minutes 15 seconds (~615 narration words)

## 1. Hook

**Visual:** Title slide on dark background, with a simple two-ring diagram: a small inner circle labelled "agent loop" and a much larger outer ring labelled "everything else".
**On-screen text:** The loop is the easy part
**Narration:** This month, almost nothing interesting happened inside the agent loop. The interesting work happened in the layer around it — tool gateways, credential delegation, context accounting, and the source control that agent output is now breaking. Vendors shipped new orchestration primitives, practitioners described building nearly identical surrounding systems without citing each other, and both camps report the same thing: the model and the loop are no longer the bottleneck. [01-c7]

## 2. Orchestration topology, vendor one

**Visual:** Quote card — "Latent Space, 12 October 2026" — over a flow diagram: lead agent writing a program box, which spawns three subagent boxes.
**On-screen text:** The lead agent writes the orchestration
**Narration:** Anthropic announced dynamic workflows. Instead of the developer pre-configuring a coordinator and a roster of subagents, the lead agent writes its own orchestration program — launching agents, collecting results, managing information flow. [01-c1] That was described in Latent Space's twelfth of October writeup of the launch. [01-c1]

## 3. Orchestration topology, vendor two

**Visual:** Quote card — "Microsoft Agent Framework blog, 16 September 2026" — showing the pull quote, beside an arrow labelled "instructions move in, tools stay remote over MCP".
**On-screen text:** Bounded competence becomes a skill
**Narration:** Microsoft's Agent Framework blog pushes what looks like the opposite way. It argues that bounded domain competences should stop being specialist agents with their own model loops, and instead move into the orchestrator's context as distributed skills, with only tools remaining remote over MCP. [01-c2] The post is careful not to overclaim — its own framing is that an autonomous agent can remain an agent, while a bounded competence can become a skill. [01-c2] We read these as complementary, not contradictory. The point is that two major vendors answered the same topology question differently in public. Treat topology as something you design now, not something you inherit from a framework default.

## 4. Two practitioners, one stack

**Visual:** Split screen. Left: "Uber — Pragmatic Engineer podcast, 14 Oct 2026". Right: "Credit Karma — AI Engineer talk, 14 Oct 2026". Shared items highlighted between them: MCP gateway, identity, context optimization, checkpointing.
**On-screen text:** Same stack. No cross-citation.
**Narration:** The strongest evidence this month isn't an announcement. On the Pragmatic Engineer podcast, around twenty-nine minutes in, Uber's engineers describe an MCP gateway that auto-generates MCP specs from their existing Thrift and Protobuf IDL registry — and later, around thirty-six minutes, projecting those same MCP servers as CLIs, because the CLI pattern is more token-efficient than loading six MCP servers into context. [01-c4] Separately, Credit Karma's Harish Gaggar walks through a comparable stack: an MCP gateway doing JWT exchange, every tool reviewed by internal security before production, PII blocked before it reaches the LLM, LangGraph checkpointing per thread and run, and a context optimizer. [01-c5] Neither source cites the other. Two teams in unrelated industries converging independently is, in our reading, the clearest sign this layer is genuine engineering rather than vendor category-creation. [01-c7]

## 5. Identity as a primitive

**Visual:** Three-row slide: "on behalf of the calling user" / "agent-scoped credentials" / "service account", each with a key icon. Footer: "LangChain Managed Deep Agents, 9 Oct 2026".
**On-screen text:** Whose credentials does the agent use?
**Narration:** LangChain's Managed Deep Agents makes the identity half of that an explicit product primitive. The developer declares, per connection, whether the agent acts on behalf of the calling user with that user's credentials, uses its own agent-scoped credentials, or uses a service account. [01-c6]

## 6. The downstream blast radius

**Visual:** Simple bar chart, two bars: May 2026 at 2,500 and September at 30,000, labelled "merged code changes per day". Source caption: "Simon Willison, 13 October 2026".
**On-screen text:** 2,500/day → 30,000/day
**Narration:** Simon Willison's thirteenth of October link blog surfaced Anthropic's account of why it replaced Git. Merged code changes went from roughly two thousand five hundred a day in May twenty twenty-six to over thirty thousand a day in September, with the replacement system built by seven people and the migration finished in five months. [01-c3] That is a source control problem created by agent throughput, not by headcount. [01-c3][01-c7]

## 7. Research pointing the same way

**Visual:** Slide: "LAGO: Language Agents with Reusable Growing Options — arXiv, 14 Oct 2026" with the number 58.6% and the caveat "self-reported, single attempt".
**On-screen text:** Agents as a reusable library
**Narration:** Research moved in the same direction. The LAGO paper proposes treating specialized agents as a persistent, reusable library of options managed by a meta-agent, reporting fifty-eight point six percent on the full five-hundred-task SWE-bench Verified split, with a frozen Qwen3.5-35B-A3B in both roles. [01-c8] The interesting part is the architecture claim — reuse across tasks without weight updates — not the headline number. [01-c8]

## 8. What the evidence does not support

**Visual:** Plain list slide, red header "Unverified".
**On-screen text:** None of this is independently measured
**Narration:** Be honest about what we have. None of the vendor announcements carry independent measurement. Microsoft's own trace comparison is labelled by its author as a three-pair illustration, not a controlled study. [01-c2] The Uber and Credit Karma accounts are self-reported descriptions of their own systems, including the token-saving figures. [01-c4][01-c5] And three perspectives are simply absent this month: independent open-source maintainers, non-US builders, and any security researcher who has actually probed these gateway patterns.

## 9. Takeaway

**Visual:** Closing slide with four bullets: tool gateway with identity delegation / per-connection credentials / context accounting / CI and source control headroom. Footer pointing to the article.
**On-screen text:** Budget for the layer around the loop
**Narration:** If you are still optimizing the loop, we think you are probably optimizing the wrong thing. Budget this quarter for the layer around it: a tool gateway with real identity delegation, explicit per-connection credential semantics, context accounting, and whatever your CI and source control need to survive your own agents' output. Prefer the practitioner accounts over the announcements when deciding what to copy — and assume every number here is self-reported until someone outside the company checks it.
